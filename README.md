## 一、项目是什么

**电商 AI 视觉工作台**：输入商品/SKU，输出可上架的一整套素材（图片 + 视频）。

核心立场（不要偏离）：

- **商品一致性优先于画面美观**——宁可少一点惊艳，也不让 AI 改坏商品。
- **能合成就别重绘**——优先生成环境，用真实商品像素合成。
- **商品事实只来自商家资料**——AI 只做整理，不做补全（材质、规格、认证、成分、功效）。
- **合规是产品能力**——显式角标 + 隐式水印 + 元数据留痕 + 审计日志 + 变更可回滚。

## 三、文档清单

### 项目交互原型

直接打开 `prototype/index.html#projects`，或从商品档案详情点击“创建项目”。可选定商品，查看规则示意的图片任务建议，调整任务与精修/质检步骤，人工确认后逐项推进。项目数据仅保存在本机浏览器；建议和预览图均为示意，不调用真实模型或计费。React Flow 开发切片另见下节。

### 项目工作流（开发切片）

先配置 `.env` 中的 `DATABASE_URL`、存储参数，以及 `PLANNER_BASE_URL`、`PLANNER_API_KEY`、`PLANNER_MODEL`（独立聊天模型；不能用生图模型代替）。启动 API：

```powershell
.venv\Scripts\python.exe -m alembic upgrade head
.venv\Scripts\python.exe -m uvicorn apps.api.main:app --reload --port 8000
```

修改 `project-ui/` 源码后，重新构建 API 提供的静态页面：

```powershell
cd project-ui
npm install
npm run build
```

打开 `http://127.0.0.1:8000/project-ui/`；旧原型的商品详情可点“创建项目”，跨页带入人工确认的字段与 SKU（仍须在新页人工核对）。AI 建议清单可逐项增删和修改，保存后再人工确认。项目页仍是受控开发切片：规划和生图均可能收费，尚无生产级预算、自动质检和节点租约恢复；详见 TD-005。

## 四、文档存放与命名约定

**后续所有需求修改与技术设计，都必须落成 md 文件放进 `docs/`，不允许只留在对话里。**

### 4.1 需求变更

```
docs/需求变更/YYYY-MM-DD-变更主题.md
例：docs/需求变更/2026-10-25-增加AI修图模块.md
```

必须写清五件事：

1. **背景**：为什么要改（用户反馈 / 上游文档遗漏 / 技术不可行）
2. **变更点**：具体改什么（原内容 → 新内容，逐条列）
3. **影响范围**：影响哪些 MVP 功能编号（M1–M9）、工期、成本
4. **不做判断**：这次改动**不包含**什么，防止范围蔓延
5. **待确认**：需要人拍板的问题

### 4.2 技术设计

```
docs/技术设计/TD-NNN-主题.md
例：docs/技术设计/TD-002-商品一致性校验.md
```

必须包含：

1. **要解决的问题**（对应哪个需求编号）
2. **方案对比**（至少 2 个选项 + 取舍理由）
3. **选定方案**（架构图 / 数据流 / 关键接口）
4. **边界与失败处理**（超时、重试、降级、成本上限）
5. **验收方式**（怎么证明它 work 了，量化指标）
6. **依赖与风险**

### 4.3 基础设施与凭据

- **中间件的地址、账号名、证书指纹、运维命令、已知坑**统一放在 `infrastructure/测试环境中间件访问说明.md`，不复制到其它文档。
- **真实密码不入库**：只放本地 `infrastructure/credentials.local.md`（`.gitignore` 的 `*.local.md` 已忽略）。仓库文档里一律用 `${XXX_PASSWORD}` 占位符。
- CA 证书放 `infrastructure/certs/`，仅作客户端校验使用。
- 轮换密码只改本地凭据文件；占位符不用动。

### 4.4 进度

- 有实质进展就追加到仓库根目录 [`PHASE.md`](PHASE.md)，格式见该文件末节。
- 进度文件只记"做了什么 + 产物/证据 + 下一步"，不复述设计。

### 4.5 文件头元信息（强制）

每份新增文档开头必须带：

```markdown
> 文档类型：需求变更 / 技术设计
> 日期：YYYY-MM-DD
> 依据：`docs/xxx.md` 或 上游功能编号（如 F04、M3）
> 影响范围：M1、M4
> 状态：草稿 / 待确认 / 已确认
```

## 六、护栏（接手者必读）

- **不要擅自扩大 MVP 范围**。`MVP需求说明` 第八节列了 10 条"明确不做"，任何一条被加回，工期至少 +2 周且不增加验证价值。
- **不要修改 `docs/电商工作台需求说明.html`**。它是上游权威输入，有变更需求时写变更文档。
- **不要用生成式模型补全商品事实**。这是合规红线，会直接导致产品不可用。
- **不要在未获明确指令前写产品代码**。当前阶段是文档与 P0 验证。
- **配图优先用内嵌 SVG**，不主动调用图像生成能力（用户对额度消耗敏感）。
- **真实密码只在本地 `infrastructure/credentials.local.md`（已被 gitignore），仓库里是占位符**。不要把凭据贴到 issue、外部文档、聊天工具或对话里转发；本地文件也不要提交。

## 七、关键数字（用于判断方案是否跑偏）

| 指标 | 阈值 |
|---|---|
| 一次通过率（不返修即可用） | ≥ 60% |
| 单 SKU 全套成本（N 张图，制作单勾选 + 15s 视频） | ≤ ¥15 |
| 单 SKU 交付时长（含人工确认） | ≤ 30 分钟 |
| 商家愿意上架比例（20 SKU 实测） | ≥ 80% |
| MVP 周期 | 约 12 周（含 2 周零代码验证） |
