# MVP 需求说明 · 电商视觉工作台

> 版本：v0.1（简化版）  
> 上游依据：`docs/电商工作台需求说明.html`（v0.9，32 个功能 / 6 大业务域 / 14 个品类）  
> 本文只定义 **第一版要做什么、不做什么、怎么算做成**。

---

## 一、MVP 到底要证明什么

不是"把 32 个功能做出来"那么简单，那叫把需求文档抄一遍。MVP 要回答三个问题，答不上来就不该继续投入：

| #      | 待验证的假设               | 判定方式                         |
| ------ | -------------------- | ---------------------------- |
| **H1** | AI 产出的素材，商家**敢直接上架** | 一次通过率 ≥ 60%（不返修即可用）          |
| **H2** | 成本结构能撑起定价            | 单 SKU 全套成本 ≤ ¥15             |
| **H3** | 效率真的比现在快             | 单 SKU 从上传到可交付 ≤ 30 分钟（含人工确认） |

**结论先行**：MVP 交付的不是功能，是**这三条证据**。功能只是取证工具。

所以裁剪原则只有一条：**能验证 H1/H2/H3 的最小闭环，一个不多；不服务于验证的，一个不做。**

## 二、范围裁剪：从 32 个功能砍到 9 个

### 2.1 取舍逻辑

原文档的 32 个功能是"完整业务地图"，不是"开发清单"。按三个问题筛：

1. **这条链路断在哪一环，闭环就跑不通？** → 保留
2. **这个功能能验证 H1/H2/H3 中的哪一条？** → 保留
3. **它只是"更好用"，不影响闭环验证？** → 砍掉

### 2.2 保留清单

| MVP 编号 | 对应原文档          | 功能         | 保留理由                           |
| ------ | -------------- | ---------- | ------------------------------ |
| **M1** | F01            | 商品与 SKU 档案 | 全流程地基，没有它寸步难行                  |
| **M2** | F03（限 3 品类）    | 品类规则       | 不按品类做，字段必漏，直接导致 H1 失败          |
| **M3** | F04            | 抠图与白底图     | 最高频、最确定、不依赖生成式 AI，风险最低的起点      |
| **M4** | F06            | 商品场景图      | **H1 的核心验证点**：AI 生成环境 + 保留真实商品 |
| **M5** | F07            | 主图与商品封面    | 商家真正拿去上架的那一张                   |
| **M6** | F29（精简）+ AI 修图 | 画布编辑与文字替换  | 不能改的 AI 出图等于不可用；改价格/改错字是日频刚需   |
| **M7** | F30（精简）        | 批量任务与费用    | **H2 的唯一数据来源**，没有它算不出单 SKU 成本  |
| **M8** | F31（精简）        | 审核、版本与交付   | 素材交不出去，前面全白做                   |
| **M9** | F21（极简）        | 商品展示短视频    | 产品叫"生图生视频"，缺视频无法证明价值；但只做最短形态   |

### 2.3 砍掉清单（V1 / V2 再做）

| 砍掉的                                            | 原因                               |
| ---------------------------------------------- | -------------------------------- |
| **跨境全套**（F19、F28、多语言多市场）                       | 多语言 + 多币种 + 多平台规则，工作量翻倍但验证的是另一件事 |
| **爆品图反推**（F18）                                 | 需要图像理解 + 配方沉淀，MVP 阶段无法保证稳定复现     |
| **营销制图**（F14–F17）                              | 海报/店铺装修/种草封面/广告 A/B，属于另一条业务线     |
| **商品精修**（F05）                                  | 抠图 + 场景已足够验证一致性，去瑕疵可延后           |
| **信息图 / 详情页 / 参数图 / 细节图 / 步骤图 / 穿搭图**（F08–F13） | 需要排版引擎 + 版式库，是"设计系统"级工程量         |
| **数字人口播 / 多语言视频 / 视频脚本系统**（F22–F28）            | 视频只验证"能不能出生效素材"，不做产能扩张           |
| **素材效果复盘**（F32）                                | 需要接投放数据，MVP 阶段商家不会给              |
| **自定义模板库**（F02）                                | 用 3–5 个内置模板代替，先不开放自定义            |
| **团队权限体系**                                     | MVP 单租户、单角色，不做角色矩阵               |

## 三、MVP 功能详述

每个功能写清：**目标 / 输入 / 流程 / 输出 / 验收 / 本期不做**。

### M1 · 商品与 SKU 档案

**目标**：一次录入真实商品资料，供后续所有制作模块调用。

| 项    | 内容                                                                        |
| ---- | ------------------------------------------------------------------------- |
| 输入   | 商品原图（≥1 张，建议 3–5 张）、商品名称、类目、卖点、规格参数、SKU 列表（颜色/尺寸/套装）                      |
| 流程   | 上传 → 表单录入（AI 可从图片/文档辅助提取，人工必须确认）→ 保存为商品主档                                 |
| 输出   | 可复用商品档案                                                                   |
| 验收   | ① 每个参数有来源标记（人工录入/AI 提取待确认）；② 修改商品后，已引用它的素材被标记"受影响"；③ 缺字段时列出待补清单，不允许空值静默通过 |
| 本期不做 | 供应商对接、批量导入 Excel、多市场销售版本、商品审核流                                            |

> **关键约束**：商品事实（材质、规格、认证、成分）只能来自商家资料，AI 只做**整理**，不做**补全**。这条不放松。

### M2 · 品类规则（限 3 个品类）

**目标**：不同品类用不同字段、场景与检查项，避免一套提示词打天下。

**MVP 只做 3 类**：

| 品类        | 必填字段              | 推荐场景         | 生成后必查            |
| --------- | ----------------- | ------------ | ---------------- |
| **美妆个护**  | 容量、成分、适用说明、包装多角度图 | 洁净白底、浴室、植物场景 | 瓶型、标签文字、净含量、Logo |
| **家居日用**  | 尺寸、材质、颜色、安装方式     | 客厅、卧室、桌面     | 空间比例、结构、表面纹理     |
| **3C 配件** | 型号、接口、兼容范围、尺寸     | 桌面、手持、接口特写   | 接口类型、孔位、产品比例     |

| 项    | 内容                                               |
| ---- | ------------------------------------------------ |
| 验收   | ① 切换品类后字段面板随之变化；② 缺必填字段时阻断生成并提示；③ 生成后按品类弹出对应检查清单 |
| 本期不做 | 其余 11 个品类、品类规则的可视化配置界面（先用代码内置）                   |

> **为什么不选服装**：服装需要模特/上身，一致性最难、返修率最高。MVP 先做**标品**，把一致性验证跑通，服装放到 V1。

### M3 · 抠图与白底图

**目标**：把供应商图和实拍图处理成干净的基础素材。**这是全流程唯一"零生成式 AI 风险"的环节。**

| 项    | 内容                                                            |
| ---- | ------------------------------------------------------------- |
| 输入   | 商品原图                                                          |
| 流程   | 智能分割得主体+蒙版 → 边缘处理 → 按模板设画布/主体占比/接地阴影 → 导出透明底 + 白底             |
| 输出   | 透明底 PNG + 白底图（可选指定纯色底）                                        |
| 验收   | ① 透明瓶、镂空、毛发不被切掉；② 白底与透明底**分开导出**；③ 支持人工补画边缘并前后对照；④ 输出尺寸符合所选渠道 |
| 本期不做 | 批量阴影模板自定义、AI 生成投影                                             |

> **技术要点**：走成熟抠图服务 + 常规图像处理，**不调用生成模型**。这一环节的成本和稳定性都要做到"几乎无感"。

### M4 · 商品场景图

**目标**：同一商品出现在适合使用的场景里。**H1 的主战场。**

| 项    | 内容                                                                   |
| ---- | -------------------------------------------------------------------- |
| 输入   | 商品主体（来自 M3 的透明底）+ 场景选择 + 构图偏好                                        |
| 流程   | 按品类选场景 → **生成环境（不含商品）** → 合成真实商品 → 调整位置/比例/透视/阴影 → 多构图候选             |
| 输出   | 场景图 3–5 张候选                                                          |
| 验收   | ① 商品大小、结构、包装**不发生任何变化**；② 主体占比符合所选模板；③ 支持局部重做（只重生成背景区域）；④ 与商品原图可并排对照 |
| 本期不做 | 自定义场景提示词、场景库市场、多商品同框                                                 |

> **关键做法**：**优先生成环境，商品用真实像素合成**。这是保住一致性的根本——只要商品不是"生成"出来的，就不存在改材质的风险。只有合成不了（角度/透视不匹配）时，才允许走可控编辑。

### M5 · 主图与商品封面

**目标**：产出平台商品列表里的第一张图。

| 项    | 内容                                                               |
| ---- | ---------------------------------------------------------------- |
| 输入   | 商品 + 目标渠道（MVP 支持 3 个：淘宝、抖音、Amazon）+ 图片用途                         |
| 流程   | 选内置模板 → 配置背景/主体占比/文案槽位 → 生成候选 → 检查安全区与小图可读性                      |
| 输出   | 主图候选（默认 3 张）                                                     |
| 验收   | ① 缩略图尺寸下仍能识别商品；② 价格、标题等文字是**独立可编辑图层**，不是烧进图里；③ 无文字主图与可含文字的附图分开配置 |
| 本期不做 | 12 个平台的完整规格库、平台直连上传、A/B 版本管理                                     |

### M6 · 画布编辑与文字替换（含 AI 修图）

**目标**：让 AI 出的图**可修改**，并支持运营最高频的"改价格/改错字"。

| 项    | 内容                                                                |
| ---- | ----------------------------------------------------------------- |
| 输入   | 已生成的图（含图层）或上传的扁平图 + 修改指令/选区                                       |
| 流程   | 见下方两条子链路                                                          |
| 输出   | 可继续编辑的设计版本                                                        |
| 验收   | ① 文字、商品、背景图层可独立操作；② 局部重做只影响选区；③ 支持撤销与版本对比；④ 改完的**文字必须回读校验通过**才算完成 |
| 本期不做 | 自动拆解任意扁平图的图层、矢量编辑、复杂排版引擎                                          |

**子链路 A · 图层内文字编辑（首选）**

```
选中文字图层 → 直接改文本 → 用真实字体重新渲染
→ 校验位置/字号/颜色未变
```

适用于：主图标题、价格标签、活动文案——只要是本系统生成的图层，改起来零风险。

**子链路 B · 扁平图文字替换（AI 修图）**

```
OCR 定位文字块（位置/字号/字色/倾斜角）
  → inpainting 擦除原字（mask 仅覆盖笔画）
  → 真实字体渲染新字 → 透视贴合
  → 回读校验：OCR 逐字比对 / 数值解析 / 版式偏移 < 5% / mask 外像素差异 ≈ 0
```

适用于：供应商图、历史素材上的价格与错别字修改。

| 规则   | 说明                                     |
| ---- | -------------------------------------- |
| 路由   | 默认走"确定性排版"；OCR 判定为艺术字/特效字时才降级到生成式替换    |
| 价格改动 | **强制二次确认** + 变更留痕（原值→新值→操作人→时间）+ 原图可回滚 |
| 阻断   | 任一校验项不通过 → 不落盘，提示具体失败项                 |

> 这是 MVP 里**留存价值最高**的功能：改价格是日频动作，生图是月频动作。它让商家天天打开产品。

### M7 · 批量任务与费用

**目标**：让批量出图有进度、有预算、失败能恢复。**H2 的唯一数据来源。**

| 项    | 内容                                                                                    |
| ---- | ------------------------------------------------------------------------------------- |
| 输入   | 商品清单 / SKU 清单 + 模板 + 生成任务                                                             |
| 流程   | 提交前估算用量与费用 → 排队执行 → 逐项状态（等待/执行/成功/失败）→ 单项重试 → 记录实际费用                                  |
| 输出   | 任务记录 + 成功素材 + 成本明细                                                                    |
| 验收   | ① 提交前显示任务数与费用估算；② 已成功项不重复扣费、不重复执行；③ 失败项可单独重试；④ 估算费与实际费分开显示；⑤ **按 SKU 汇总成本**（支撑 H2 计算） |
| 本期不做 | 配额套餐、发票、跨团队额度分配、优先级队列                                                                 |

### M8 · 审核、版本与交付

**目标**：把候选稿变成可追溯的已确认素材，并打包交出去。

| 项    | 内容                                                                       |
| ---- | ------------------------------------------------------------------------ |
| 输入   | 待审素材 + 目标渠道                                                              |
| 流程   | 批注 → 修改 → 版本对比（v1→v2→v3）→ 确认 → 按渠道分目录打包导出                                |
| 输出   | 已确认版本 + 素材包（ZIP）                                                         |
| 验收   | ① 批准版本可追溯；② 导出清单标明文件名、数量、尺寸、SKU 对应关系；③ 旧版本可标记过期但不删除；④ 单人审核即可（MVP 不做多人流程） |
| 本期不做 | 多角色权限、评论 @人、平台后台直连发布、可编辑工程导出                                             |

### M9 · 商品展示短视频（极简）

**目标**：证明"图 → 视频"能出生效素材，**不做产能扩张**。

| 项    | 内容                                                                           |
| ---- | ---------------------------------------------------------------------------- |
| 输入   | 已确认的主图 + 场景图 + 商品卖点（1–2 句）                                                   |
| 流程   | 固定 3 段式模板：`主图推近（3–5s）→ 场景切换（3–5s）→ 细节展示（3–5s）` → 生成/拼接 → 加字幕 + BGM → 导出 9:16 |
| 输出   | 15 秒竖版 MP4（含字幕）                                                              |
| 验收   | ① 商品在各镜头中身份一致（无闪烁、无形变）；② 音画同步、字幕不遮挡主体；③ 单条成本可统计；④ 时长/比例/编码符合导出配置             |
| 本期不做 | 口播/数字人、多语言、脚本分镜系统、多比例输出、实拍混剪、BGM 曲库                                          |

> **视频只做一种形态**，是因为它的成本占全套 80%（见方案文档 §7）。MVP 的任务是测准这个成本，不是把视频做全。

## 四、页面与主流程

### 4.1 六个页面

| 页面              | 干什么                               |
| --------------- | --------------------------------- |
| **商品列表 / 商品详情** | 档案录入与维护（M1、M2）                    |
| **制作台**         | 选品类 → 选场景 → 生成 → 看候选（M3、M4、M5、M9） |
| **画布编辑器**       | 图层编辑、选区重做、文字替换（M6）                |
| **任务中心**        | 批量任务、进度、费用（M7）                    |
| **素材库 / 交付**    | 版本、审核、导出（M8）                      |
| **设置**          | 品牌基础（Logo/主色/字体）、模型配置             |

### 4.2 主流程（一条线走完）

```
新建商品 → 填档案（M1/M2）
      ↓
上传原图 → 抠图出白底（M3）
      ↓
选场景 → 生成场景图候选（M4）
      ↓
套模板出主图（M5）
      ↓
画布调整 / 改价格改错字（M6）
      ↓
批量跑其余 SKU（M7）
      ↓
审核确认 → 打包导出（M8）
      ↓
（可选）生成 15s 展示视频（M9）
```

## 五、最小数据模型

```
Product     商品主档：id / 名称 / 品类 / 卖点 / 参数(带来源标记) / 状态
Sku         变体：product_id / 颜色 / 尺寸 / 套装 / 售价
Asset       素材：id / product_id / sku_id / 类型(原图|白底|场景|主图|视频)
                  / 文件路径 / 生成参数 / 父版本 / 状态
Job         任务：id / 类型 / 对象 / 状态 / 尝试次数 / 估算费 / 实际费
Version     版本：asset_id / v序号 / 操作人 / 变更说明 / 是否已确认
CategoryRule 品类规则：品类 / 必填字段 / 推荐场景 / 检查清单
BrandKit    品牌：logo / 主色 / 字体 / 禁用词
AuditLog    留痕：对象 / 操作 / 原值 / 新值 / 人 / 时间
```

> `Asset.parent_version` + `AuditLog` 这两张表是**合规与回滚的底**，MVP 阶段就必须有，不能等 V1 补。

## 六、技术约束（MVP 阶段主动降级）

> 架构细节见 `docs/技术设计/TD-001-总体技术架构.md`（中间件、数据模型、状态机）。模型/渠道接入方案待后续单独确定。本节只列约束，不重复设计。

| 项 | MVP 做法 | 为什么 |
|---|---|---|
| 用户体系 | 单租户、单角色，但表结构从第一天带 `tenant_id` | 权限矩阵不影响验证 H1/H2/H3；字段预留避免后期全表改 |
| 中间件 | PostgreSQL 17（事实源）+ Redis 7（队列/进度/限流）+ MinIO（素材） | 三件套已拍板；Redis 可丢可重建，事实不落 Redis |
| 任务队列 | Arq + Redis，四队列隔离（image / video / media / vision） | 生图、视频轮询、ffmpeg、OCR 负载特性不同，混跑会互相拖死 |
| 模型接入 | 火山引擎（Seedream / Seedance），**不做多厂商模型路由** | 路由是优化项；但保留渠道适配层，换渠道只改配置 |
| 渠道策略 | 聚合渠道为主 + 方舟官方按能力兜底 | 成本优先，同时保证图层拆分等新参数可用 |
| 一致性校验 | 只做 2 项硬指标（CLIP 相似度 + OCR 文字比对）+ M6 拆分无损校验 + 人工复核 | 全量 5 项校验的工作量大于收益 |
| 部署 | 单机 docker-compose 八容器 + MinIO | 不做 CDN、不做高可用；media worker 独占 CPU |
| 平台规格 | 内置 3 个渠道的常用尺寸 | 12 平台规格库是纯体力活 |

> 新增两条不能算"降级"的底线：① 每次模型调用必须落计费流水（否则 H2 无从验证）；② 服务重启不能丢任务（否则 H3 失守）。这两条不因 MVP 而省略。
>
> **2026-10-23 变更**：MVP 增加单管理员登录、审计日志、成本看板/单价表；素材改为「槽位 + 版本」并采用软删；字段阻断改为按 `generate / delivery` 分级。详见 `docs/需求变更/2026-10-23-系统与数据模型定稿.md` 与 `docs/技术设计/TD-004-商品素材与生产流程.md`。

## 七、验收标准

### 7.1 量化指标（Go / No-Go）

| 指标             | 阈值                   | 不达标怎么办          |
| -------------- | -------------------- | --------------- |
| **一次通过率**      | ≥ 60%                | 停下来改一致性策略，不许加功能 |
| **单 SKU 成本**   | ≤ ¥15                | 重算视频重试率与模型选型    |
| **单 SKU 交付时长** | ≤ 30 分钟              | 检查人工确认环节是否过重    |
| **商家愿意上架比例**   | ≥ 80%（抽 20 个 SKU 实测） | 说明产出不达"可上架"标准   |

### 7.2 功能验收（对齐原文档 AC-01 / AC-05 / AC-04）

- **AC-M1 商品一致性**：多品类真实商品跑主图/场景图，核对结构、颜色、Logo、包装文字、规格；发现不一致时能定位并局部修正，原图可追溯。
- **AC-M2 批量与恢复**：任务包含失败、取消、重试、部分成功；进度与费用可见；成功结果保留；失败项可单独重试。
- **AC-M3 编辑与交付**：同一商品连续做场景图与主图并修改价格；文字可独立编辑、局部修改不影响其他部分；导出数量/尺寸/SKU 对应正确。
- **AC-M4 视频连续性**：15s 视频中商品身份一致；无闪烁、形变、黑帧；替换单镜头后保留其他部分与编辑历史。

## 八、明确不做（防止范围膨胀）

以下任何一条被临时加进 MVP，都意味着工期至少 +2 周，且**不增加 H1/H2/H3 的验证能力**：

- ❌ 跨境 / 多语言 / 多币种 / 多市场
- ❌ 爆品图反推
- ❌ 海报、店铺装修、种草封面、广告 A/B
- ❌ 详情页长图、参数对比图、信息图
- ❌ 模特上身 / 虚拟试穿 / 服装品类
- ❌ 数字人口播、多语言视频、脚本分镜系统
- ❌ 素材效果复盘（接投放数据）
- ❌ 自定义模板市场
- ❌ 多角色权限、团队协作
- ❌ 平台后台直连发布

## 九、排期与人力

**建议配置**：后端 2 + 前端 1 + 算法/提示词 1，共 4 人。

| 阶段            | 周期  | 产出                                              |
| ------------- | --- | ----------------------------------------------- |
| **P0 · 技术验证** | 2 周 | 不写产品代码。手工跑 10 个真实 SKU，测一次通过率与单 SKU 成本。**不达标就停** |
| **P1 · 地基**   | 2 周 | M1 商品档案 + M3 抠图白底 + 素材存储                        |
| **P2 · 核心链路** | 3 周 | M4 场景图 + M5 主图 + M6 画布与文字替换                     |
| **P3 · 交付闭环** | 2 周 | M7 批量任务 + M8 审核交付                               |
| **P4 · 视频**   | 2 周 | M9 15s 展示视频                                     |
| **P5 · 真实跑批** | 1 周 | 3 个商家、20 个 SKU 实测，出验收报告                         |

合计约 **12 周**（含 P0）。如果 P0 结论不达标，总周期归零，这是好事——省下了后面 10 周的返工。
