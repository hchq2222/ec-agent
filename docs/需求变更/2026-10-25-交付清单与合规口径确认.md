# 需求变更 · 交付清单与合规口径确认

## 一、背景

TD-004 定稿时留了 5 项「待确认」，其中 3 项会直接影响 `0006_assets` 与 `0007_jobs` 的表结构和导出逻辑；品类范围则必须在 `0003_products` 之前定，否则字段与迁移会返工。

本次把其中 4 项拍板，剩余 2 项（回收站保留期、登录切换窗口）不阻塞地基，继续挂起。

> 注：上游 `docs/电商工作台需求说明.html` 仍按「8 图」描述默认交付；本变更只调整 MVP 的实施口径，**不回改上游 HTML**。

## 二、变更点

| # | 原内容 | 新内容 |
|---|---|---|
| 1 | 品类范围未定，服装是否进 MVP 待议 | **只做美妆 / 家居 / 3C，服装放 V1**。通过 `category_rule_version` + `category` 字符串预留扩展；不预埋服装专用字段、不加模特/试穿流程 |
| 2 | 「8 图」定义未定：固定 8 位 vs 模板定义 | **取消固定 8 图**，改为**自由选择**：制作单勾选「用途 + 数量」；每个选中项 = 一个 `JobItem`；同用途多张用 `slot_no` 区分；导出按选中清单一一核对，不预设「缺位」 |
| 3 | 合规标识落盘方式未定 | **导出时合成**：库内 `asset_version` 保留无标识母版；导出包合成显式角标 + 隐式水印 + 元数据；同一母版换渠道可重新合成，不重新生成 |
| 4 | 批量任务粒度未定 | **每 SKU 一个 `Job` + `parent_job_id` 归组**；取消、续跑、成本都以 SKU 为单位（正式确认） |

配套调整：

- `asset` 增加 `slot_no`，唯一键改为 `(sku_id, usage, channel, size_spec, slot_no)`。
- `job_item` 增加 `usage`、`slot_no`，与目标 `asset` 槽位一一对应；`selected_items` 记录提交时的清单。
- `export_job.manifest` 增加 `selected_items` 与 `compliance` 配置，导出包与选中项必须一一对应。
- 制作单定稿条件：**选中项全部 final 且通过校验**；不再检查「8 位是否齐」。

## 三、影响范围

| 维度 | 影响 |
|---|---|
| MVP 功能 | M2（3 品类，结构预留）、M3–M8（交付清单自选）、M7（每 SKU 一 Job）、M8（导出合成合规标识） |
| 数据迁移 | `0003` 无额外表；`0006` 的 `asset` 增 `slot_no`；`0007` 的 `job_item` 增 `usage/slot_no`；导出表增 `selected_items/compliance` |
| 流程 | 制作单从「模板 8 位」改为「勾选清单」；导出由「补缺位」改为「按清单核对」 |
| 验收 | AC 由「8 张齐全」改为「选中项一一对应」；新增合规导出验收（A10）与品类扩展验收（A11） |
| 成本 | 预算切分不变（图 ¥5 / 视频 ¥10 / 返工 ¥3，硬上限 ¥18）；N 受硬上限约束，超限转人工 |
| 工期 | 不增加；`slot_no` 与清单是 0006/0007 内的小改动 |

## 四、不做判断（本次不包含）

- 不做固定 8 位模板，也不做「缺位补图」提示——自由选择下不存在预设缺位。
- 不做按品类的交付位模板市场。
- 不做服装品类及其模特/试穿流程（V1）。
- 多用户与角色 UI、Excel 导入、跨商品复用仍按原计划。

## 五、待确认

1. **软删回收站保留期**：当前定 30 天，是否与客户合同/审计要求一致。
2. **登录上线节奏**：推荐「先写审计、再强制鉴权」两步，需确认切换窗口。
3. **omyai 计费换算**：token → 单张/单秒单价或账单，用于回填 `price_book`（数据问题，非产品决策）。
4. **聚合渠道最终选型**：影响价格、限流与能力可用性（商务决策）。
