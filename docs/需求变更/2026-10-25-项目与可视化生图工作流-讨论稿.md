# 需求变更 · 项目与可视化生图工作流（讨论稿）

## 一、背景

现有制作单要求人先选用途与数量，再逐项生成。用户希望选定商品后，由大模型依据已确认的商品资料、SKU、目标渠道和预算，先规划符合电商用途的图片任务清单，再逐项生图、精修和交付；同时希望用 React Flow 在可视化画布上调整生产步骤。

当前 D8 已决定交付清单自由选择、每个选中交付项对应一个 `JobItem`；本讨论的关键是让 AI 提建议并让用户编辑，同时不改变已拍板的成本、商品一致性与交付口径。

## 二、变更点（拟议）

| 现有口径 | 拟议口径 | 约束 |
|---|---|---|
| 商品/SKU → 人手工勾选制作单 | 商品/SKU → 项目 → AI 建议交付清单 → 用户编辑/确认 → SKU 制作单 | 项目是生产上下文，不替代商品事实源、制作单或素材槽位 |
| 交付项主要以用途、数量表达 | 每项建议带用途、目标渠道/尺寸、张数、建议理由、所需商品证据、优先级、预估费用、依赖与失败风险 | AI 只使用来源明确且已确认的事实；缺证据要标记，不得补造功效、材质、规格等；当前实现只覆盖用途、SKU、标题、描述、理由和尺寸，其余待补 |
| 制作流程固定展示 | 为每个交付项展示可编辑的有向无环工作流：素材准备 → 构图/环境 → 合成或受控生成 → 校验 → 人工复核 → 定稿 | 默认优先真实商品像素合成；生成整件商品或改商品事实须受现有 L1/L2/L3 规则限制 |
| 生成与精修散在页面动作里 | 工作流节点承载“生成候选、选稿、局部精修、文字图层、质量/合规校验、人工确认、导出准备”等步骤 | 精修产出新版本，不覆盖已确认版本；每次模型调用都落计费流水 |
| React Flow 尚未接入 | React Flow 用于节点/边的编辑和执行进度可视化；服务端校验工作流并执行 | 图画布的 UI 状态与可执行流程分离；服务端是唯一执行与状态事实源 |

建议的主流程：选商品/SKU → 读取已确认事实与原始素材 → AI 输出结构化建议清单 → 展示预算与缺证据项 → 用户调整/确认 → 为每个交付项选择或编辑工作流 → 服务端校验 → 逐项生成候选/精修/校验 → 人工确认 → 按选定清单交付。

AI 规划结果应包含依据的商品版本、规则版本、目标渠道、规划模型版本与清单版本。规划失败时可退回手工自由选择；重复规划产生新草稿，不自动覆盖用户已确认的清单。提交后冻结本次清单和工作流快照；后续编辑产生新版本并只影响未开始的执行项。

目标节点库包括输入素材、抠图/白底、生成环境、商品合成、受控生图、候选选择、局部精修、文字图层、质量校验、人工确认和产物入槽。当前开发切片先落输入、受控生图、可选精修、人工质检、人工确认和交付标记，且执行仅支持单条线性路径。预算、并行、节点失败后的安全续跑及完整节点库均需后续完善，详见 TD-005。

React Flow 官方文档提供自定义节点、连线校验、保存/恢复以及防止循环的示例；这些是编辑器能力。工作流执行、持久化、幂等、预算和审计仍由本项目后端实现。

## 三、影响范围

| 维度 | 影响 |
|---|---|
| 现有对象 | 商品/SKU 仍是事实源；`Job` 仍按 SKU，`JobItem` 仍按选中交付项；项目只组织规划与执行上下文，不把每个工作流节点误当成一张交付图 |
| 数据与版本 | 需要项目、AI 规划快照、工作流定义/版本、节点执行记录与既有 Job/JobItem/Asset/ProviderCall 的关联；具体表结构待技术设计 |
| 页面 | 增加项目入口和规划清单；制作台展示项目中的交付项与流程；任务中心显示节点进度、单项失败、费用；素材库继续以槽位/版本管理 |
| 成本与排期 | AI 规划本身也产生模型费用；本期纳入可执行可视化编排，需重估工期，不沿用原 12 周假设 |
| 验收 | 同一商品事实版本可复现清单；人工确认前不触发付费生图；可编辑后通过服务端校验；失败节点可恢复且不重跑已成功交付项；产物、费用和审核可回溯到项目/清单/流程版本 |

## 四、不做判断（本讨论暂不包含）

- 不让 AI 擅自生成未经商家确认的商品事实、功效宣称或平台合规结论。
- 不让 React Flow 前端直接调用渠道、决定计费或成为任务状态事实源。
- 不引入任意脚本节点、第三方插件市场、跨商家共享模板或多人协作。
- 不改变已确认的“每 SKU 一个 Job”“交付项一个 JobItem”“导出时合成合规标识”。
- 不把视频分镜系统加入现有 M9；未来可复用同一工作流基础，但需单独确认节点与验收。

## 五、决策与剩余边界

1. **项目边界（已确认）**：一个项目对应一个商品，可包含该商品的多个 SKU；执行和成本仍按 SKU，不跨商品。
2. **执行授权（已确认）**：AI 任务清单须经人确认后，才开始付费生图；规划阶段仅展示建议、缺失依据与预算预估。规划模型调用本身如产生费用，仍须记录计费流水并纳入预算。
3. **自定义深度（已确认）**：使用系统提供的限定节点，允许在 React Flow 中自由连线和调整步骤；节点端口按类型校验，服务端拒绝循环、缺少必需校验/人工确认、不可用模型及超预算的流程；不开放任意脚本节点。
4. **MVP 分期（已确认）**：本期同时实现 AI 任务规划和可执行的 React Flow 限定节点工作流；排期需据实际实现重新估算，不沿用原 12 周假设。
5. **AI 清单建议范围**：仅建议现有主图/白底/场景/细节/视频用途，还是扩到详情长图、信息图、广告图？后者与当前 MVP 排除项冲突，需单独变更范围。
