# TD-004 · 商品、素材与生产流程重构

## 一、要解决的问题

四场讨论暴露出同一个结构性问题：**当前的生图能力是"孤岛"**。

| 现状 | 后果 |
|---|---|
| 商品只存在 prototype 的 localStorage | 素材、任务、成本都无法归属到 SKU |
| `asset` 一行 = 一个文件 | 无法表达"这张主图的 v1/v2/当前交付版" |
| `job` 没有 `product_id / sku_id / job_item` | 生成结果无法回填商品，也无法按单张重试 |
| `DELETE /api/jobs` 直接删 DB + MinIO 对象 | 与"素材不可再生、版本可回滚、审计不可改"冲突 |
| 字段来源 `ai` 未确认就整档阻断 | "包装图未传"会拦住白底图，H3（30 分钟）必超 |
| `provider_call.amount` 全为空 | H2（单 SKU ≤ ¥15）无法取证 |
| 没有登录与 `audit_log` 落库 | "操作人"只能写 `system`，合规留痕形同虚设 |

## 二、方案对比

### 2.1 素材的主对象

| 选项 | 做法 | 问题 |
|---|---|---|
| A · 文件为主 | 一行一个文件（现状 / TD-001 原始设计） | v1/v2 互相独立，"当前交付版本唯一"无法表达 |
| B · 版本为主 | 一行一个版本 | 导出与批量操作要按"这张主图"选，不是按"第 3 版" |
| **C · 槽位 + 版本** | `asset` = SKU×用途×渠道×尺寸；`asset_version` = 产物 | 多一张表，但审核、回滚、导出语义干净 |

**选 C。**

### 2.2 删除语义

| 选项 | 做法 | 问题 |
|---|---|---|
| A · 硬删 | 删任务即删对象（现状） | 违反"原图/版本不可再生、可回滚" |
| **B · 软删 + 回收站** | `deleted_at`，30 天后清理；原图永不物理删 | 需要清理任务，但可恢复 |

**选 B。**

### 2.3 字段阻断

| 选项 | 做法 | 问题 |
|---|---|---|
| A · 全档案阻断 | 任一字段非 human → 全部生成禁用（现状） | 白底图被"包装多角度图"卡死 |
| **B · 按 `block_scope` 分级** | `generate` 才拦生成；`delivery` 只拦交付 | 需要字段级配置 |

**选 B。**

### 2.4 制作台与生图工作台

| 选项 | 做法 | 问题 |
|---|---|---|
| A · 合并 | 一个页面兼顾自由生成与 SKU 流水线 | 自由生成的调用污染单 SKU 成本与通过率分母 |
| B · 并列 | 两个入口各自独立 | 工作台产物无法成套交付 |
| **C · 上下游** | 工作台 = 素材工厂（产物进"未归档"）；制作台 = 交付流水线（带 SKU 上下文） | 需要"归入 SKU"动作 |

**选 C。**

## 三、选定方案（六条决策）

| # | 决策 | 结论 |
|---|---|---|
| D1 | 素材模型 | **槽位 + 版本**：`asset`（槽位）1:N `asset_version`（产物），文件只是 `object_key` |
| D2 | 删除语义 | **软删 30 天回收站**；原图永不物理删；`DELETE /api/jobs` 改为软删/仅删未归档 |
| D3 | MVP 登录 | **单 admin + Cookie 会话**；不做注册/短信/SSO/多用户 UI，表结构预留 |
| D4 | 字段阻断 | **`block_scope` 分级**（generate / delivery）；高敏字段逐项确认 |
| D5 | 成本口径 | **含废弃稿、返工、视频**；`price_book` 快照 + 调用日汇率；原币与人民币双金额 |
| D6 | 工作台产物 | **进"未归档"收件箱**，显式「归入 SKU + 交付位」并通过 L3 后才进素材包 |

配套原则（沿用，不重新讨论）：

- 一致性优先：L1 合成优先，L2 可控编辑必须过 L3，L3 失败硬阻断（价格/文字/结构是硬项，美观是软项）。
- 任务粒度：`Job` → `JobItem`（一个交付位）→ `ProviderCall`。
- 草稿/定稿：`draft` 低配多候选 → 选定后 `final` 升档。
- 商品事实：解析/提取一律 `ai`，人工确认后才变 `human`。

### 3.2 生产流程与状态

```text
SKU 制作单：未开始 → 草稿中 → 待复核 → 已定稿 → 已打包
                                  ↑        ↓
                          需复检 ← 商品档案变更 / 素材受影响

JobItem：pending → queued → running → succeeded
                      ├→ failed（基础设施错误，重试 ≤3，不计费）
                      └→ needs_manual（校验不过 / 超预算 / 内容拦截）
                              → 人工：通过 / 重做（计费） / 弃
```

- 一次 SKU 提交 = 一个 `Job`；每个交付位 = 一个 `JobItem`；`n=4` 是同一 item 的 4 个候选，不是 4 个 item。
- 批量 = N 个 SKU 各一个 `Job`，用 `parent_job_id` 归组；取消/续跑/成本都以 SKU 为单位。
- 校验失败**只自动重生成 1 次**，之后转人工，避免预算被吞。

### 3.3 成本口径

```
单 SKU 成本 = 该 SKU 全部 provider_call.amount 之和
              （含废弃稿、返工、失败但计费的调用）
单 SKU 交付 = 8 图 + 15s 视频全部为 final 且通过校验
```

- 成本页三栏：估算 / 实际 / 返工占比；另有「待定价流水」（`amount IS NULL`）支持人工补单价并回填。
- 币种：`provider_call` 同时保存原币金额与 `amount_cny`，`fx_rate` 落调用当日快照。
- 预算切分建议：图 ¥5 / 视频 ¥10 / 返工 ¥3，单 SKU 硬上限 ¥18，超限暂停转人工。

| 页面 | 变化 |

| 商品档案 | 列表改表格 + 「待补清单」聚合；详情拆 6 区（基础/必填/SKU/图片证据/变更影响/审计） |

## 四、边界与失败处理

### 4.1 迁移顺序（不可颠倒）

| 迁移 | 内容 | 依赖 |
|---|---|---|
| `0003_products` | product / product_attr / sku / sku_attr / category_rule_version | 无 |
| `0004_system` | user / role / permission / role_permission / session / audit_log | 无 |
| `0005_billing` | price_book；provider_call 增 `job_item_id`（先可空）、`price_book_id`、`fx_rate`、`amount_cny` | 0003/0004 |
| `0006_assets` | asset 重构 + asset_version + asset_impact + 软删字段；旧 asset 行映射为 version v1 | 0003 |
| `0007_jobs` | job 增 product_id/sku_id/parent_job_id/type/step/template_id/budget；新增 job_item | 0003/0006 |

### 4.2 现有行为调整

| 现状 | 调整 |
|---|---|
| `DELETE /api/jobs/{id}` 硬删 | 改为软删（`deleted_at`）；仅"未归档且从未确认"允许硬删；原图永不允许 |
| `asset` 一行一图 | 迁移为 `asset` 槽位 + `asset_version` v1；`object_key` 移入 version |
| 自由生成自动进库 | 默认 `asset.product_id IS NULL` = 未归档；提供「归入 SKU」动作 |
| 生成不校验档案 | 提交任务前服务端校验 `block_scope=generate` 字段；前端不可信 |
| `provider_call.amount` 空 | 允许为空；成本页提供"待定价流水"回填入口，不伪造金额 |

### 4.3 兼容与回滚

- 每个迁移提供 `downgrade`；`0006` 保留旧列一版周期，确认无读依赖后再删。
- 商品 localStorage 数据不自动迁移：提供一次性导入脚本，导入后逐条人工确认来源。
- 登录上线采用"先建账号、后开鉴权"两步：先落 `user`/`session` 并写审计，再切强制登录，避免把现有接口一次性打断。

## 五、验收

| # | 验收项 | 通过标准 |
|---|---|---|
| A1 | 商品入库 | 商品/SKU 全部在 PG；localStorage 仅作离线草稿 |
| A2 | 素材槽位 | 同一 SKU 同一用途多版本，`current_version_id` 全局唯一且指向已确认版本 |
| A3 | 软删 | 删除后 30 天内可恢复；原图不可被物理删除 |
| A4 | 阻断分级 | 缺 `delivery` 字段仍可生成白底图；缺 `generate` 字段服务端拒绝提交 |
| A5 | 成本可算 | 任一 SKU 能查出估算/实际/返工占比；`amount` 为空的调用单独列出 |
| A6 | 审计可用 | 改价、删素材、改渠道 Key、改单价均写 `audit_log`，含 actor 与原值新值 |
| A7 | 归属完整 | 制作台产物带 product/sku/usage/channel；工作台产物默认未归档 |
| A8 | 迁移无损 | 迁移前后 asset 数量、字节数、对象可访问性一致 |

## 六、依赖与风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 迁移顺序颠倒 | asset 无 product_id 可填 | 严格按 0003→0007，禁止跳步 |
| 旧 asset 映射丢版本语义 | 历史素材无法审核 | 全部映射为 v1，审核状态置"待确认" |
| 登录一次切全量 | 现有接口全部 401 | 两步上线：先写审计，再强制鉴权 |
| 软删清理误删 | 素材不可再生 | 清理任务只处理"软删 >30 天 + 无引用 + 非原图" |
| 成本回填靠猜 | H2 失真 | 只允许从 `price_book` 取价，禁止写死金额 |
| 工期 | 地基约 +3 周 | 先做 0003–0005，再动 UI；UI 不等全部迁移完成可先接商品 |
