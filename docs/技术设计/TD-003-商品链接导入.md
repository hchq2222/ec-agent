# TD-003 · 商品链接导入

## 一、要解决的问题

M1 要求"一次录入真实商品资料"，但手工填一个 SKU 的名称、参数、价格至少 3–5 分钟。用户希望：粘贴商品详情页链接，自动提取名称、价格、参数，一键录入。

约束（来自项目红线）：

- **商品事实只来自商家资料，AI 只整理不补全**。解析结果只能作为"待确认草稿"，不能直接当事实。
- 不能因为解析失败阻断录入：必须保留手工录入路径。

## 二、方案对比

| 选项 | 做法 | 问题 |
|---|---|---|
| A · 手工录入 | 现有表单 | 成本高，是本次要解决的问题 |
| B · 平台开放 API | 淘宝/京东开放平台商品接口 | 需要商家授权、审核周期长；跨境平台各自一套 |
| C · 页面结构化提取 | 抓 HTML，优先 JSON-LD，其次 OpenGraph/meta，最后标题+价格兜底 | 反爬与 JS 渲染会失败，需要明确降级 |
| D · 第三方采集服务 | 调外部解析 API | 成本、稳定性、数据合规都不可控 |

**选 C**：无外部依赖，能覆盖独立站 / Shopify / 部分开放平台；失败时明确报错并引导手工录入。

## 三、选定方案

### 3.1 提取优先级

```
GET 链接（20s 超时，3MB 截断，Chrome UA）
  → 1. JSON-LD schema.org/Product
        name / description / image / offers.price / priceCurrency / brand / additionalProperty
  → 2. OpenGraph / meta
        og:title / og:description / og:image / product:price:amount
  → 3. <title> + 页面文本价格正则（¥ / ￥ / $ / € / £）
  → 仍无商品名 → 422，提示"站点可能需要登录或由 JS 渲染"
```

货币判断按符号优先：`¥/￥ → CNY`、`£ → GBP`、`€ → EUR`、`$ → USD`。

### 3.2 接口

```http
POST /api/products/parse-link
{ "url": "https://item.taobao.com/item.htm?id=..." }
```

```json
{
  "data": {
    "url": "https://...",
    "source": "json-ld | opengraph | html",
    "product": {
      "name": "商品名",
      "price": 129.0,
      "currency": "CNY",
      "description": "描述",
      "image": "https://...",
      "attributes": { "容量": "150ml", "品牌": "森序" }
    },
    "warnings": ["价格来自页面文本匹配，需人工核对"]
  }
}
```

**只返回草稿，不写库**。入库由前端确认后完成。

### 3.3 前端流程

```
商品档案 → 🔗 链接导入
  → 输入链接 → 分析链接（loading）
  → 展示：名称 / 价格 / 描述 / 参数表 / 主图
  → 选品类（美妆 / 家居 / 3C）
  → 一键录入
      → 参数按品类必填字段模糊匹配，命中标 `ai`（待确认），未命中标 `missing`
      → 价格生成 1 条默认 SKU
      → 写入 localStorage（原型阶段），并写入 audit（链接导入商品）
  → 自动选中新商品，详情页可继续编辑 / 确认字段
```

### 3.4 安全

| 项 | 做法 |
|---|---|
| SSRF | 只允许 http/https；解析域名并拒绝 private / loopback / link-local / reserved IP |
| 体积 | 响应截断 3 MB，避免超大页面拖垮进程 |
| 超时 | 20s，失败返回 `TIMEOUT` 可重试 |
| 反爬 | 401/403 返回明确文案，引导手动录入 |
| 事实红线 | 解析结果一律 `ai` 来源，必须人工确认才变 `human` |

## 四、边界与失败处理

| 场景 | 行为 |
|---|---|
| 淘宝/京东详情页（JS 渲染 / 反爬） | 大概率 403 或提取不到名称 → 明确提示，转手动录入 |
| 独立站 / Shopify / WooCommerce | JSON-LD 命中率高，参数较完整 |
| 价格是区间或多个 SKU | 取 `offers.price` / `lowPrice` 或页面首个价格，标注"需人工核对" |
| 币种识别错误 | 以符号优先判断；仍不确定时留空，由用户填写 |
| 解析到名称但无参数 | 允许录入，字段标 `missing`，制作台会阻断生成直到补齐 |
| 链接是短链 / 跳转 | 跟随重定向；最终 URL 回传 |
| 内网地址 | 400 拒绝 |

**不做**：绕过登录/验证码、批量抓取、平台账号授权、自动入库。

## 五、验收

| 项 | 结果 |
|---|---|
| JSON-LD 提取（离线） | ✅ 名称 / 价格 / 币种 / 品牌 / 参数全部命中 |
| OpenGraph 兜底（离线） | ✅ meta 名称与价格 |
| 标题 + 价格兜底（离线） | ✅ `<title>` + `¥88.50`，并给出"需人工核对"警告 |
| 真实页面 | ✅ books.toscrape（`html`，£51.77）、webscraper 测试站（`opengraph`，$24.99） |
| SSRF | ✅ `http://127.0.0.1:8000/healthz` 返回 400「不允许访问内网地址」 |
| 前端 | ✅ 商品档案页新增「链接导入」，导入后商品进入列表并选中，字段标 AI 待确认 |

## 六、依赖与风险

| 风险 | 对策 |
|---|---|
| 目标平台改版 / 反爬升级 | 提取优先级分层，任何一层失效仍可降级；失败不阻断手工录入 |
| 参数名与品类字段不一致 | 前端模糊匹配；未命中标 `missing`，人工补齐 |
| 解析结果被当成事实直接使用 | 强制 `ai` 来源 + 详情页逐项确认；制作台在未确认时阻断生成 |
| 抓取合规（平台 ToS /  robots） | 只解析用户主动提供的单个链接，不做批量采集；上线前过法务 |
| 商品未落库（当前 localStorage） | 原型阶段可接受；M1 正式实现时接 `product` / `sku` 表与 `audit_log` |
