# TD-002 · 生图能力接入（omyai / OpenAI 兼容）

## 一、要解决的问题

第一阶段只接一个渠道（`https://omyai.vip`，New API 类中转，OpenAI 兼容协议），但需求里明确"未来会加更多生图和生视频"。所以这次不只是"能调通"，而是要把**扩展成本压到改配置**：

| 需求 | 约束 |
|---|---|
| 现在能出图 | `POST /api/images/generate` 同步返回可访问的图片 URL |
| 模型可选 | 前端从 `GET /api/models` 拿列表，不在代码里写死模型 |
| 加模型不改代码 | 新模型 = `config/providers.yaml` 加一条 |
| 加渠道不改业务 | 新渠道 = 一个 adapter 类 + 一段配置 |
| 后续加生视频 | 复用同一套 Registry / 错误码 / 存储，只新增 `VideoProvider` |

## 二、方案对比

| 选项 | 做法 | 问题 |
|---|---|---|
| A · 直接写死 | 在路由里 `httpx.post("https://omyai.vip/v1/images/generations", ...)` | 换模型要改代码；加第二家渠道要复制粘贴；错误处理散落 |
| B · 一模型一类 | `GPTImage2Client`、`FluxClient`… 每个模型一个类 | 类爆炸；同渠道不同模型 90% 逻辑重复 |
| **C · Provider + Model 注册表** | Provider 管协议与渠道，Model 管能力声明与上游 ID，业务只认 model key | 多一层抽象，但换渠道/加模型都不碰业务代码 |

**选 C。** 这也是 TD-001 里 `apps/providers/` 的落点。

## 三、选定方案

### 3.1 结构

```
业务 / API
   │  只认 model key（如 gpt-image-2）
   ▼
Registry ── 读 config/providers.yaml
   │         ├─ 能力校验（n / size / quality / 参考图张数）
   │         └─ 找到 provider 实例
   ▼
Provider（adapter）
   ├─ openai_compat  → omyai、one-api/new-api、OpenAI 官方
   └─ （预留）ark / replicate / fal / comfyui
   ▼
上游 HTTP
```

### 3.2 三个概念

| 概念 | 含义 | 变化频率 |
|---|---|---|
| **Provider** | 协议 + 渠道：`base_url`、鉴权方式、调用形态 | 低（换厂商才变） |
| **ModelSpec** | 对外 key、上游模型 ID、能力、计价口径 | 高（上游上新很频繁） |
| **Capabilities** | 该模型允许什么：张数、尺寸、质量、参考图、mask | 随模型 |

能力校验放在 Registry，**不放在 adapter**：这样任何渠道都走同一套参数规则，前端拿到的错误也一致。

### 3.3 代码结构

```
apps/
  api/
    main.py          FastAPI 入口（/api/models、/api/images/generate、/files）
    schemas.py       请求/响应模型
  core/
    config.py        环境变量与 .env
    storage.py       产物落盘（接口留给 MinIO）
  providers/
    base.py          ImageProvider 协议、ModelSpec、能力、统一错误码
    openai_compat.py OpenAI 兼容 adapter（generations + edits）
    registry.py      YAML → provider/model 注册表，参数校验
config/
  providers.yaml     渠道与模型清单（**唯一需要改的地方**）
scripts/
  smoke_image.py     命令行冒烟：列模型 / 真实生成
```

### 3.4 配置即扩展

```yaml
providers:
  - id: omyai
    type: openai_compat
    base_url: https://omyai.vip/v1
    api_key_env: OMYAI_API_KEY      # 只存变量名，密钥在 .env
    models:
      - key: gpt-image-2
        model: gpt-image-2
        kind: image
        capabilities:
          max_n: 4
          sizes: ["auto", "1024x1024", "1536x1024", "1024x1536"]
          qualities: ["auto", "low", "medium", "high"]
          output_formats: ["png", "jpeg", "webp"]
          backgrounds: ["auto", "opaque", "transparent"]
          image_input: true
          max_ref_images: 16
```

|---|---|---|

### 3.5 API 契约

**`GET /api/models?kind=image`**

```json
{
  "data": [
    {
      "key": "gpt-image-2",
      "provider": "omyai",
      "kind": "image",
      "display_name": "GPT Image 2",
      "capabilities": {
        "max_n": 4,
        "sizes": ["auto", "1024x1024", "1536x1024", "1024x1536"],
        "qualities": ["auto", "low", "medium", "high"],
        "output_formats": ["png", "jpeg", "webp"],
        "backgrounds": ["auto", "opaque", "transparent"],
        "image_input": true, "mask": true, "max_ref_images": 16
      },
      "pricing": { "unit": "image", "price": null, "currency": "USD" }
    }
  ]
}
```

**`POST /api/images/generate`**

```json
{
  "model": "gpt-image-2",
  "prompt": "白色陶瓷马克杯，纯白背景，电商主图，柔和顶光",
  "n": 1,
  "size": "1024x1024",
  "quality": "high",
  "output_format": "png",
  "background": "opaque",
  "images": [],
  "mask": null,
  "extra": {}
}
```

返回：

```json
{
  "id": "img_9f2c1a7b3d4e",
  "model": "gpt-image-2",
  "provider": "omyai",
  "images": [{ "url": "http://127.0.0.1:8000/files/2026/10/22/img_...png", "mime": "image/png", "bytes": 1834201 }],
  "latency_ms": 18234,
  "usage": { "images": 1 }
}
```

产物落本地 `var/outputs/年/月/日/`，通过 `/files` 静态访问。**落盘在 API 进程内完成**，不把上游的临时 URL 直接给前端（中转站的 URL 通常会过期）。后续换 MinIO 只替换 `LocalStorage`。

### 3.6 统一错误码

| 内部码 | 触发 | HTTP | 可重试 |
|---|---|---|---|
| `AUTH_FAILED` | 上游 401/403，或未配置密钥 | 502 | 否 |
| `RATE_LIMITED` | 上游 429 | 429 | 是 |
| `INVALID_PARAM` | 参数不合法 / 上游 400·422 | 400 | 否 |
| `CONTENT_BLOCKED` | 内容安全拦截 | 422 | 否 |
| `TIMEOUT` | 上游超时 | 504 | 是 |
| `PROVIDER_ERROR` | 上游 5xx / 响应结构异常 | 502 | 是 |
| `MODEL_NOT_FOUND` | 模型 key 不存在 | 404 | 否 |
| `CAPABILITY_UNSUPPORTED` | 模型不支持该能力（如参考图） | 400 | 否 |
| `ARTIFACT_LOST` | 产物下载失败 | 502 | 是 |

> `AUTH_FAILED` 返回 502 而不是 401：这不是**调用方**没权限，而是**我们服务端**的渠道配置有问题，不该让前端以为用户需要重新登录。

## 四、边界与失败处理

| 场景 | 当前行为 | 说明 |
|---|---|---|
| 单次调用超时 | 默认 180s，返回 `TIMEOUT` | 生图常见 10–60s；超时值在 YAML 可调 |
| 上游限流 | 原样返回 `RATE_LIMITED`，**不自动重试** | 重试应放在任务层（TD-001 的 `JobItem` + 退避），避免同步接口长时间挂起 |
| 内容拦截 | 映射 `CONTENT_BLOCKED`，不计费重试 | 引导换素材，不重试 |
| 上游返回 URL | adapter 立即下载并落盘 | 不把临时 URL 透给前端 |
| 产物下载失败 | `ARTIFACT_LOST`（可重试） | 不再重新生成，避免重复扣费 |
| 参考图过多 | 按 `max_ref_images` 拦截 | 不做静默截断 |
| 密钥缺失 | `AUTH_FAILED`，提示变量名 | 启动不校验（允许先起服务），调用时才暴露 |
| 响应不是 JSON | `PROVIDER_ERROR` | 记录状态码，便于排查中转站异常页 |

**MVP 不做**：异步任务队列、自动重试、成本记账、多渠道路由。这些在 TD-001 的任务层统一做（`JobItem` / `ProviderCall` / `price_book`），生图接口保持"薄"。

## 六、依赖与风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 渠道密钥无效/被禁用 | 无法出图 | 重新签发后只改 `.env`，代码零改动；错误已明确提示 |
| 中转站模型名与官方不一致 | 调用 404/400 | 模型 ID 在 YAML，可单独改；能力以实测为准 |
| 中转站静默忽略参数 | 花了钱拿到非预期结果 | 关键参数（size/quality）在验收清单里逐项实测 |
| 上游 URL 过期 | 前端拿到死链 | adapter 立即下载落盘，前端只拿本地 URL |
| 同步接口耗时过长 | 前端请求超时 | MVP 接受；批量出图走后续任务队列 |
| 计费不透明 | 成本不可控 | 调用层预留 `usage`/`pricing` 字段，后续接 `provider_call` 流水 |
| 图片内容合规 | 素材违规 | 后续接 TD-001 的合规官与标识注入，不在本层处理 |

## 附 · 扩展指南

### 加一个新模型（最常见，1 分钟）

在 `config/providers.yaml` 对应 provider 的 `models` 下加一条：

```yaml
      - key: gpt-image-3
        model: gpt-image-3
        kind: image
        capabilities:
          max_n: 4
          sizes: ["auto", "1024x1024"]
          image_input: true
```

重启服务即生效，`/api/models` 自动出现。

### 加一个新渠道（半天）

1. 在 `apps/providers/` 新建 adapter（实现 `generate` 与 `aclose`）。
2. 在 `apps/providers/registry.py` 的 `ADAPTERS` 注册 `type`。
3. `config/providers.yaml` 加一个 provider 块。
4. 补一组 MockTransport 单测。

业务代码、API 契约、前端都不用动。

### 加生视频（下一步）

- 新增 `VideoProvider` 协议：`submit()` / `poll()` / `cancel()`（生视频是异步任务，不能照搬同步生图）。
- 新增 `VideoRequest` / `VideoResult` / `kind: video`。
- Registry 复用，`GET /api/models?kind=video` 直接可用。
- 任务编排（提交 → 轮询 → 转存）交给 TD-001 的 `video` 队列，不在 API 进程里做。
